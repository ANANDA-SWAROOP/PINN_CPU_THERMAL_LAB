# CPU Thermal Digital Twin — v5 PINN companion

This folder contains a self-contained presentation UI and an optional local inference API for the audited v5 notebook.

## Two modes

- **Illustrative simulation:** runs immediately in the HTML file. The example scenarios (turbo burst, sustained rendering, bursty compilation, and recovery) are synthetic, presentation-only profiles. The displayed field is generated by a small spatial-kernel + thermal-inertia demo. It is clearly labelled and is **not** output from the PINN, a measured trace, or a calibrated CPU model.
- **Trained PINN inference:** loads the trained v5 `pinn_best` state, training feature scalers and temperature scalers. With the optional recorded data asset, it predicts a temperature map for the selected CPU frame and compares it against that frame's recorded map.

The notebook's normalized time variable `tau` represents normalized sample order `0..1`, not elapsed physical seconds. The export also stores the training/validation/test frame IDs so the dashboard marks each recorded frame with its split; use TEST frames when discussing held-out performance.

## 1. Start the visual demo (no Python or model needed)

Open `cpu_thermal_digital_twin.html` directly in a browser. The four synthetic time-series presets, playback controls, intensity adjustment, heatmap and demo CSV export work offline.

For consistent local model API access, serve the page over HTTP rather than opening it as `file://`:

```bash
cd cpu_thermal_digital_twin
python -m http.server 8080
```

Open `http://127.0.0.1:8080/cpu_thermal_digital_twin.html`.

## 2. Export your actual trained model and dataset from Colab

1. Run the audited v5 notebook through the end of training and evaluation. Ensure `pinn_best.pt` exists in `results_v5/checkpoints/`.
2. Add the code from `EXPORT_FROM_COLAB.py` as a **new final code cell** and run it.
3. Colab downloads `cpu_thermal_simulator_assets.zip`. It contains:
   - `pinn_simulator_bundle.pt`: the trained PINN weights, exact feature/temperature normalization statistics, architecture metadata and input shape.
   - `recorded_cpu_dataset.npz`: original-order raw feature vectors and corresponding observed temperature maps.
   - `sample_features.csv`: the 80 raw input features per frame for reusing a custom sequence in the UI.
   - `metadata.json`: dataset and units notes.

Extract those four files into the `assets/` folder next to `model_service.py`. The HTML dashboard does not require the asset files for demo mode.

You can also copy the code in `EXPORT_FROM_COLAB.py` into the notebook directly; the included file is a convenience copy, not a standalone training script.

## 3. Run the real PINN inference API

Use Python 3.10+ in a virtual environment. Install dependencies:

```bash
python -m venv .venv
# Linux / WSL
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Start the service from this folder:

```bash
uvicorn model_service:app --host 127.0.0.1 --port 8000
```

Check `http://127.0.0.1:8000/health`. It should report `model_loaded: true` and `dataset_loaded: true` if the assets were exported and placed correctly.

Then open the HTML app served on port 8080, press **Connect**, and select **Recorded CPU i5 / 7zip** from the time-series dropdown. The left map is the model's prediction and the right map is the recorded label. The dashboard reports MAE, RMSE, top-5% hotspot IoU and peak-location error for that frame. Play or scrub to inspect other frames.

## 4. Upload an alternate feature series

In the UI, you can upload a CSV with exactly 80 numeric feature columns, one row per frame. Keep the exact feature order used for training. Do not prepend an index, time or workload-percentage column. Blank/NaN feature values are imputed using the saved training feature mean. The uploaded series can be run through `/predict`; because no ground-truth maps are supplied in this case, test metrics are not shown.

The synthetic workload sliders are not converted into 80 model features. This is intentional: inventing a mapping from a one-dimensional `load%` value to the 80 trained input features would be scientifically invalid.

## 5. What to say in the presentation

- Before the model is connected: “This is an illustrative thermal-inertia visualizer to explain the interaction between workload, hotspots and cooldown; these numbers are synthetic.”
- After the model is connected: “These maps are predictions from our trained v5 PINN, compared against held-out recorded CPU temperature maps.” Only make accuracy claims supported by the notebook's held-out test evaluation. Do not treat the presentation playback itself as a new training or validation experiment.

## API

- `GET /health` — model/dataset readiness.
- `GET /recorded-series` — recorded-map peak/mean timeline summaries.
- `GET /predict-recorded/{frame_index}` — full map inference + paired ground truth + metrics.
- `POST /predict` — `{ "features": [80 raw values], "tau": 0.0 }` for an alternate feature series.
